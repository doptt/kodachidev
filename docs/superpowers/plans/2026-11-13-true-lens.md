# True Lens for the Projects Sky: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The projects sky uses the real gravitational lens at every pixel, and a settled project is still a flat, readable rectangle.

**Architecture:** The easing in the lens shader is removed. Each project's picture is painted on the sky in the shape that the real lens, seen from the camera's resting place, bends back into a flat rectangle: per pixel, the true sky direction is turned back to the project's resting place and passed through the inverse of the deflection table to get a point on the resting screen. The camera rests a little higher (radius 2.5), the framing is rebuilt round the Einstein ring's true position, and star brightness follows the lens's real magnification.

**Tech Stack:** TypeScript (strict), hand-written WebGL2 / GLSL ES 3.00, `node --test` for the pure maths, Playwright stills for the look.

**Spec:** `docs/superpowers/specs/2026-11-13-true-lens-design.md`. Read it first. This plan argues from it.

## Review Focus

1. **The window is resized or a phone is turned mid-scene.** The resting pose depends on the aspect; a stale one leaves the settled picture bent. Expected: flat again on the next frame. Pinned in Task 1 (flat at every aspect) and Task 3 (the cache key).
2. **Very tall and very wide screens** (aspect 0.4, 3.6). Expected: the resting picture is wholly outside the ring and wholly on screen. Pinned in Task 2.
3. **One project, or nine.** Expected: never more than `MAX_SOURCES` lit, nothing readable but the settled one at rest, no picture coming round a second time. Pinned in Task 2.
4. **A ray that ends exactly at the zenith, exactly behind the hole, or inside the shadow.** The turn-back has no azimuth there. Expected: a finite coordinate or "not in the picture", never NaN (a NaN pixel blooms into a black or white block). Pinned in Task 1.
5. **The GL context is lost and restored.** Expected: the inverse table comes back with the deflection table. No node test can reach this; Task 3 makes them share one creation path and `ready`.

```ts
export const INVERSE_SIZE = 256
/** Entry i is the angle from straight down at which sky angle PI * i / (INVERSE_SIZE - 1) is seen directly. */
export function inverseTable(table: Float32Array, r0: number, out?: Float32Array): Float32Array
/** Reads it the way the shader does: linear between entries, phi clamped to 0..PI. */
export function inverseLookup(inverse: Float32Array, phi: number): number
/** Camera axes for a yaw and a pitch above level, column-major: right, up, forward. Moved from renderer.ts unchanged. */
export function cameraBasis(yaw: number, pitch: number): Float32Array
/** The ray through a point of the screen given as tangents (x right, y up) from the camera's axis. Unit length. */
export function screenRay(basis: Float32Array, x: number, y: number): [number, number, number]
/** The sky direction a ray ends up at, as the shader computes it with the true lens. Null inside the shadow. */
export function lensed(table: Float32Array, r0: number, d: readonly number[]): [number, number, number] | null
/**
 * Where a sky direction lies in a project's picture: tangents on the resting screen's plane, measured
 * from the picture's centre. `turn` is how far the project is from its resting place, radians about
 * the x axis (0 when settled, positive further round behind the hole). Null when it lies behind the
 * resting camera. Never NaN.
 */
export function pictureCoord(sky: readonly number[], turn: number, inverse: Float32Array, restBasis: Float32Array, centreY: number): [number, number] | null
```

`pictureCoord` is the algorithm the shader repeats, so it is fixed here:

```ts
// 1. Turn the sky direction back to the project's resting frame (a rotation about x by -turn)
const c = Math.cos(turn), s = Math.sin(turn)
const y = sky[1] * c + sky[2] * s
const z = -sky[1] * s + sky[2] * c
const x = sky[0]
// 2. Where the resting camera sees that direction directly: same azimuth, the inverse table's angle
const phi = Math.acos(Math.min(1, Math.max(-1, y)))
const flat = Math.max(Math.hypot(x, z), 1e-5)
const psi = inverseLookup(inverse, phi)
const d = [(Math.sin(psi) * x) / flat, -Math.cos(psi), (Math.sin(psi) * z) / flat]
// 3. Onto the resting screen's plane
const q = [dot(right, d), dot(up, d), dot(forward, d)]   // the columns of restBasis
if (q[2] <= 0.02) return null
return [q[0] / q[2], q[1] / q[2] - centreY]
```

  gap?: number
  /** Picture height as a share of the screen's height. Default min(mix(0.3, 0.44, wide), 0.88 * aspect / 1.6). */

  /** Top edge of the picture, NDC. Default mix(0.6, 0.86, wide). */
  top?: number
}
export type Framing = {
  tanHalfFov: number
  /** Resting camera pitch above level, radians. Negative: the camera looks down past the limb. */
  pitch: number
  /** Top of the shadow's limb on the screen's centre line, NDC. */
  horizon: number
  /** Where the Einstein ring crosses the screen's centre line, NDC. */
  ring: number
  /** Picture centre, tangents above the camera's axis, on the screen's plane. */
  centreY: number

}
/** `edge` and `ring` are angles from straight down at the resting radius. */
export function framing(aspect: number, edge: number, ring: number, tune?: Tune): Framing

`framing` is fixed by these lines (`wide`, `tanHalfFov` as in today's `composition`):

```ts
const high = tune.high ?? Math.min(mix(0.3, 0.44, wide), (0.88 * aspect) / 1.6)
const top = tune.top ?? mix(0.6, 0.86, wide)
const bottom = top - 2 * high
const pitch = ring + (tune.gap ?? rad(4)) - Math.PI / 2 - Math.atan(bottom * tanHalfFov)
// horizon = tan(edge - PI/2 - pitch) / tanHalfFov, ring likewise
// centreY = (top - high) * tanHalfFov, half = [1.6 * high * tanHalfFov, high * tanHalfFov]
```

- Radius: `R_OPEN` at `x = 0`, climbing to `rest` by `x = 0.85 * INTRO` (smootherstep, interpolating `log(r - 1)`), holding, then falling to `R_END` exactly as today.
- `sources` gain becomes `smoothstep(-1, -0.55, ahead) * (1 - smoothstep(1.7, 2.3, ahead))`: a picture that has left is dark by the time the next has settled.
- Produces, in `picture.ts`:

```ts
export type Rest = {
  radius: number
  framing: Framing
  table: Float32Array      // deflection table at `radius`
  inverse: Float32Array    // its inverse
  basis: Float32Array      // the resting camera
  thetaRead: number        // sky angle, from the zenith, seen at the picture's centre

```
